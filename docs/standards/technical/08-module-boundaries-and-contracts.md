# 技术 08 · 模块边界与内部契约

> 版本：1.0.0 · 日期：2026-10-04
> 依据：ADR-0031、[ADR-0039](../../adr/0039-module-boundaries-and-internal-contracts.md)。
> 稳定约束正文在本文件；具体施工／验收见[模块整改 Plan](/Users/ldh/Downloads/project/plan/mode/README.md)。存量代码未整改不等于规则自动不适用，真实状态以 ROADMAP 为准。

#### R-M1 · 逻辑模块与部署边界分开

- **等级**：MUST
- Built-in App 有 appId、数据、UI 和按需 Runtime 实例；Internal Module 只有所属应用内的职责与接口，不增加产品、Host、卡片、独立库 authority 或 Release。
- 不因拆模块新增 daemon、通用 RPC、消息中间件、服务发现或第二分发链。
- 跨进程沿现有受控通道；同进程优先直接业务函数／已有 trait，不为调用“像 API”而增加内部 HTTP。

#### R-M2 · 接口包含完整行为契约

- **等级**：MUST
- 公开操作明确输入／输出、权限上下文、版本／幂等、错误、取消及资源界限。
- 优先复用领域类型；接口不能暴露可写数据库连接、SDK 私有类型、HTTP handler 或页面内部对象。
- 业务层返回业务类型／错误；协议层负责 JSON、HTTP／Native 映射与 i18n 错误展示。
- 单一真实实现足够时可用函数／具体类型；不为每个文件创建 trait、Repository、DI 或 pass-through 层。

#### R-M3 · 依赖方向按职责

- **等级**：MUST
- HTTP／Native 适配和后台任务调用同一所属业务用例；业务／任务不反向依赖 handler、页面、DOM 或传输 body。
- 纯计算只处理已校验值；有副作用的用例明确组织事务、网络、Secret 和取消，不伪装纯 helper。
- 日期、格式和公共查询投影放在有明确职责的模块，不把路由层当公共工具库。
- 复杂业务校验／跨表写入不能只存在于 handler；简单查询可封装在所属查询／Store，不要求每 SQL 独立 Repository。

#### R-M4 · 一份业务权威与完整事务

- **等级**：MUST
- 应用存储／迁移 owner 管理唯一业务库；内部领域通过操作协作，不建立第二账本、金额缓存 writer 或每领域独立库。
- 跨领域原子用例由一个事务 owner 编排；事务内可通过包内受限上下文共享当前 connection／transaction，但不暴露为公共接口或跨 appId 能力。
- 不能锁内网络、同锁重入、以多次 HTTP 替代原子写入；commit 后释放 guard，再 query。
- 首页、持仓和卡片派生同一规则与明确快照 identity；部分值、无价、未知成本、缺历史不补零。

#### R-M5 · 公共状态与私有实现分开

- **等级**：MUST
- 共享展示状态有明确 writer 和公开读／更新接口；跨职责只读共享可以合法，但调用方不能改写 owner 的内部对象。
- 私有快照、draft、图表实例、请求句柄、timer 与任务 registry 由所属模块管理；通过最小 selector、操作或事件协作。
- 不用暴露全量 `state`／对象集合替代接口，不对大对象盲目复制或引入新状态框架。

#### R-M6 · 装配与依赖可验证

- **等级**：MUST
- 页面 controller 负责装配；Broker／client／纯能力不反向 import 上层 controller。分析包含静态 import、字面量动态 import 与 re-export。
- 公开动作有唯一注册 owner；后续同步用显式编排或订阅，不捕获旧函数后隐式覆盖。
- 初始化依赖先声明／注册，再启动；未就绪或缺能力明确错误，不能用空守卫静默丢工作。
- 静态 IIFE bundle 可保留，装配顺序、公开操作和 disposer 必须可测。

#### R-M7 · SDK 与外部数据在适配边界

- **等级**：MUST
- 上游 SDK 的类型、状态、配置和错误转换位于声明的适配模块；组合入口只装配，Host 业务不直接解释上游实现。
- 行情、NAV、资讯提供来源／业务时间／质量与有界错误，不成为账本权威。
- 凭据继续只由 Keychain 持久化；接口和证据不泄漏 Secret。不得借解耦更换 SDK 主版本或扩大管理面。

#### R-M8 · 资源 owner 随代码移动

- **等级**：MUST
- 移动任务／缓存／订阅时一并移动或明确其创建、取消、deadline、等待、上限与清理责任。
- 复用当前 Host／Runtime 生命周期机制，不复制第二 registry。stopping 后拒绝新副作用，迟到结果不写已关闭存储。
- EOF、hidden、pagehide、异常 disconnect、BFCache 与取消按现行性能／前端规范验证；不能用强制 GC、广杀进程、吞错误或只等进程结束掩盖资源缺陷。

#### R-M9 · 契约与版本一致

- **等级**：MUST
- `BuiltInAppModule`／`ModuleService`／`ModuleContext`、生产实现、示例与检查保持一致；保留生命周期与服务分离，业务 HTTP 不拿生命周期大锁。
- 模块元数据、registry、编译描述、签名产品清单、激活投影与 Client 协议协同验证。
- 不兼容协议、篡改能力或未来 schema 在业务写入前拒绝；不回退固定端口、旧 Host 或未鉴权路径。
- 使用当前受信字段，不按前端自报 verified／版本或“同主版本”替代兼容证明。

#### R-M10 · 开发与正式代码更新分开

- **等级**：MUST
- 源码内核更新仅限受核验的隔离开发身份及开发源。正式身份在下载／构建／换装前拒绝，并给真实可行动错误。
- 正式代码更新沿唯一产品交付、验签和激活链；不新建独立内核发布／更新引擎。
- 保留开发更新的单任务、取消、目标校验、依赖／补丁约束、stage 和失败恢复；主版本迁移另行决策，不手动更新绕过按钮。

#### R-M11 · 扩展按现有契约接入

- **等级**：MUST
- 新 Built-in App 实现统一 Library 契约、静态注册、受信元数据／能力／views 和独立数据，随完整候选验证；公共 Shell／Runtime 不加入其业务分支。
- 新内部模块先定业务、数据和资源 owner，复用所属应用的类型／事务，不增 appId／DB／Host。
- 不为未知未来用途预建框架；新增通用共享代码仍须至少两个真实生产调用方。

#### R-M12 · 门禁与完成声明诚实

- **等级**：MUST
- 既有检查覆盖声明的第一方生产后端／UI／核心入口，缺入口须失败；不得把只检查关键词／行数描述成完整依赖审计。
- 新边界规则有违规与合法正反例，检查 import 环、反向依赖、私库访问、核心业务分支、动作 owner 与契约漂移。
- 第三方／fixture／生成资源按真实身份分类，不扩大例外掩盖缺陷；无法静态解析的动态依赖明确覆盖边界并在生产入口约束。
- 发布前完成项目必需门禁与实际调用链；Release／Chrome／平台层级分开，未验不标 PASS。施工、验收和证据规则不替代安全授权。
