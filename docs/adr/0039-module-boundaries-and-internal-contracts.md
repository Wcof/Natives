# ADR-0039 · 模块内部边界、公共契约与施工验收

- 日期：2026-10-04
- 状态：已接受设计；源码整改待按 Plan 实施和验收。
- 决策依据：用户确认保留主架构，授权完善方案、更新设计与工程规范，并交由其他 AI 完整实施。
- 范围：补充 ADR-0031；保留 ADR-0033／0035～0038、安全、数据、资源及产品交付边界。
- 施工入口：[模块整改 Plan](/Users/ldh/Downloads/project/plan/mode/README.md)。

## 背景

现有 Host／App 边界基本符合规划，但 Fund 领域与任务反向引用 HTTP 层，前端暴露私有状态／图表并存在动作覆盖，Extension 含动态 import 的依赖成环，SDK 类型扩散到 Host 业务。关键词门禁无法完整验证上述边界。

技术 07 的 `start(router)` 示例与已实现的 `start() -> Arc<dyn ModuleService>` 不一致；目录示例又把领域统一描述为无副作用，却没有区分纯计算与必须持久化的业务用例。需要校准契约和规则，不能据此恢复旧 Runtime 或机械拆分文件。

## 决策

1. **部署不变**：一个 Natives 产品、Files Host、Model Host、统一 App Runtime 和短命 Launcher。内置应用静态编译、按 appId 独占按需进程；不新增 daemon、通用 IPC、消息总线、服务发现、独立模块发布或每领域数据库。
2. **内部职责自治**：Fund 按账本、估值／收益、外部数据、目标／分析、通知和查询投影组织。领域协作走包内业务接口；业务与任务不反向依赖 HTTP handler、页面或传输格式。
3. **副作用可定位**：纯计算只接受已校验数据；业务用例在明确 owner 下组织事务、网络和 Secret 窄能力。复杂规则与跨表写入不留在 handler；简单查询由所属查询／Store 封装，不强制每 SQL 创建 Repository。
4. **事务不拆散**：Fund 保持单 `fund.db` 和存储／迁移 owner。事务内包内协作允许受限 connection／transaction，禁止对外暴露可写连接、跨 appId 共库或同锁重入。账本事实与估值／展示投影分开。
5. **接口保持实际统一模型**：采用现有 `BuiltInAppModule` 和 `ModuleService` 的生命周期／服务分离；Runtime HTTP 不在生命周期锁中执行业务。技术 07 同步实际签名／字段；公共接口变更同时更新生产 caller、契约和一致性检查。
6. **前端接口显式**：公共展示状态有唯一 writer；私有快照、图表、请求和草稿不泄漏；每个 action 唯一 owner，装配显式。静态 IIFE 可以保留，但不能用隐式覆盖和空守卫掩盖依赖未就绪。
7. **SDK 适配收口**：上游 SDK 类型／状态转换停留于已有明确适配位置；Host 业务使用项目类型。不是为每个 SDK 结构建立镜像框架，也不授权升级 CLIProxy 主版本。
8. **安全发布不分叉**：开发源码内核更新只允许隔离开发身份；正式身份在下载／构建／换装前拒绝。正式代码更新沿唯一产品验签／激活链，不新增第二更新引擎。
9. **验收检查真实边界**：扩展既有门禁检查声明的第一方入口、Rust 反向依赖、JS 静态／字面量动态导入环、私库访问、前端公开动作和契约一致性，并有正反例。正文由技术 08 统一维护，Plan 负责施工与逐项证据。

## 对原规则的精确修订

技术 07 的目录树改为职责示意：现有按领域命名的平铺文件及明确子目录均可，不要求创建无实际职责的 `domain/storage/migration` 空目录。若旧“必须严格遵守”被解释成固定物理目录，此 ADR 明确替代该解释；长期约束是职责、接口、依赖和 owner 可审查。

“领域核心纯业务、无外部 side-effect”限定为纯计算部分；持久化业务用例必须有明确副作用 owner，不因它含 SQLite 而伪造纯函数，也不允许副作用任意散落。这是职责细化，不放宽事务、安全和数据权威。

ADR-0033 已接受的顶栏只读库降级仍有效，仅为其明确消费方和只读范围；不能解释为所有新模块均可读其他 owner 私库。

## 后果与实施状态

新增稳定规范技术 08；更新技术 01／05／06／07、前端结构／状态、托管应用契约和导航。保持现有对外协议、精度、schema、功能与 UI；明确的时间／错误传播缺陷单独回归。

本 ADR 接受目标设计，不宣称现有代码已符合所有新增约束。旧引用和缺陷按 Plan T00～T10 处理，A01～A36、Release 和真实 Chrome 为证据要求；平台／供应商／正式发布证据独立列状态。源码整改进度只在 ROADMAP 汇总。
