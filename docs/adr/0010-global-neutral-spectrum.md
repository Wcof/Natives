# ADR 0010: Global Neutral Spectrum and Monochrome Data Visualization

> **Status**: Accepted  
> **Date**: 2026-07-14  
> **Supersedes**: ADR 0009 中“单色仅适用于 Dashboard”的范围限制

## Context

ADR 0009 将 Dashboard 收敛为黑白灰界面，但没有定义足够完整的中间色阶，也没有把单色品牌扩展到全部第一方界面。仅使用黑、白和少量灰色会造成两个问题：界面层级依赖边框堆叠，图表也无法清楚表达从低到高的体量差异。

全局主题需要一套稳定的黑到白光度阶梯，同时保留错误、警告、成功、信息、Diff 与终端 ANSI 等必须依靠色相识别的语义颜色。

## Decision

1. 全部第一方 UI 共享一套固定的 15 级中性色板；深色与浅色主题不各自发明颜色，只反转语义角色的取值方向。
2. 用户已确定的关键锚点保持不变：`#010101`、`#18181A`、`#27262B`、`#9B999E`、`#FAFAFC`。
3. 背景、表面、边框、文字、控件、选中态必须消费语义令牌，业务组件不得直接选择原始色阶。
4. 数据图表使用独立的 `chart-volume-0` 至 `chart-volume-8` 顺序色阶。深色主题从暗到亮表示体量增加，浅色主题从亮到暗表示体量增加。
5. 普通体量分布不得使用错误/成功等语义色。彩色仅保留给 danger、warning、success、info、Diff、终端 ANSI 和用户内容。
6. 图表色阶使用固定实色，禁止通过临时 opacity 或背景混色制造数据等级。颜色不能作为唯一信息载体，必须同时提供数值、标签或 Tooltip。
7. 默认使用线性体量映射；若使用平方根或对数映射处理长尾数据，图例必须明确标注，Tooltip 仍展示真实值。
8. 本 ADR 先更新规范，不代表代码已经完成迁移；实际令牌和组件改造必须在独立任务中实施并验证。

## Alternatives Considered

- **黑、白、灰三色体系**：实现最少，但无法稳定表达表面层级和图表体量，拒绝。
- **运行时颜色插值**：可生成任意级数，但不同组件容易采用不同算法并产生视觉漂移，拒绝。
- **页面各自维护色板**：短期灵活，但破坏全局主题一致性，拒绝。

## Consequences

- `docs/standards/ui-ux/01-design-tokens.md` 成为中性色板、语义角色和图表用色的唯一权威来源。
- 深浅主题可以在保持同一品牌语言的同时获得足够的背景、边框、文字和数据密度层次。
- 图表实现需要统一迁移到固定的体量令牌；现有临时灰色、透明度和品牌彩色不再符合规范。
- ADR 0009 仍保留其“语义状态色不能灰度化”和 Dashboard 克制表达的决策，其页面范围由本 ADR 扩展到全局第一方 UI。
