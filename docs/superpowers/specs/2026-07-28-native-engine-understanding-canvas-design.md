# Native 引擎理解、审计与配置画布设计

- 状态：待用户评审
- 日期：2026-07-28
- 范围：Settings → 执行引擎 → Native 引擎
- 关联设计：`2026-07-26-native-harness-control-plane-design.md`

## 1. 目标

执行引擎首页必须让不懂 Agent、Harness、Hook 或 Prompt 的用户完成三件事：

1. **看懂**：5 秒内知道 Native 引擎现在能不能工作。
2. **理解**：沿一张画布理解请求如何被处理，以及问题会影响哪一步。
3. **配置**：点击节点后进入该步骤真正支持的 Harness、Hook、Prompt 或能力配置。

同一张画布还必须支持选择一条真实 Run 进行执行审计。用户沿与“工作原理”相同的路径，核对本次实际使用的 Harness、Prompt、Hook、模型与工具证据。

## 2. 已选方向

比较过三个方向：

| 方向 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| A. 结论 + 执行路径 | 同时支持理解、定位和配置；健康时也有持续价值 | 需要严谨设计两层节点 | **采用，并升级为画布主界面** |
| B. 健康检查与修复中心 | 出问题时处理最快 | 健康时价值弱；原理与高级配置被藏深 | 不采用 |
| C. 完整技术拓扑优先 | 工程信息密度最高 | 新用户无法在 5 秒内理解 | 仅作为“展开技术节点” |

画布是主界面，不是在工程表单下附加一张图。固定执行拓扑由引擎提供；用户不能删除、重排或重新连线。

## 3. 首屏信息架构

首屏从上到下只有四层：

1. **范围与模式**
   - 范围默认跟随当前项目；没有当前项目时显示全局引擎。
   - 用户可手动切换范围。
   - 模式为“工作原理”与“执行审计”。两种模式复用节点位置与连线。
2. **一句结论**
   - `可以正常工作`
   - `部分功能受到影响`
   - `当前无法工作`
   - 同时显示问题数量和一个主要操作；结论不得由 Renderer 猜测。
3. **执行画布**
   - 默认显示 5 个白话节点。
   - 技术名只作为次级标签或提示。
   - “展开技术节点”显示引擎返回的完整固定拓扑。
4. **节点详情抽屉**
   - 点击节点打开右侧抽屉，桌面端不遮住全部路径。
   - 窄屏改为底部抽屉，保留返回画布入口。

默认画布节点：

| 用户节点 | 用户理解 | 对应真实技术阶段 |
|---|---|---|
| 收到请求 | 接收目标、项目和上下文 | `session` |
| 准备身份与规则 | 决定身份、规则和要携带的提示词 | `context` |
| 调用 AI 模型 | 选择并请求可用模型 | `provider` |
| 使用能力 | 判断工具、确认权限、执行工具或子 Agent | `tool_gate`、`permission`、`tool_execute`、`subagent` |
| 返回结果 | 整理上下文、判断停止并返回结果 | `compact`、`stop`、`terminal` |

`cross_stage` 是技术视图中的跨阶段通知总线，不伪装为第六个普通用户步骤。

归并只改变表现层。每个用户节点必须携带其真实 stage IDs，状态和审计证据均由这些真实节点聚合，Renderer 不生成合成执行事实。

## 4. 两种画布模式

### 4.1 工作原理

工作原理模式回答三个问题：

- 这一步做什么？
- 为什么需要它？
- 出问题会影响什么？

每个节点显示名称、一个短句、健康状态和问题数。点击后，抽屉默认打开“看懂”页签；高级字段默认折叠。

### 4.2 执行审计

进入执行审计后必须先选择一条真实 Run。未选择、没有 Run、Run 尚无 Harness 快照时分别显示诚实空态，不能用示例 Run 填充。

选择 Run 后，同一张画布覆盖这次执行的冻结证据：

- 未经过：该分支本次没有执行；
- 执行中：存在开始事件但尚无终态；
- 符合预期：冻结快照和事件满足确定性检查；
- 有差异：实际解析结果与所选预期版本或范围不同；
- 执行失败：存在结构化失败或完整性错误；
- 证据不足：旧 Run、迁移前 Run 或事件缺失，不能给出正确性结论。

审计模式不得读取当前 Draft 作为历史 Run 的证据。Run 的冻结 Harness snapshot、Prompt Plan 摘要、capability snapshot reference 和已持久化 `run_events` 是唯一依据。

## 5. 节点状态模型

健康状态和单次执行状态是两条独立信号，不得合并成一个颜色：

| 信号 | 状态 | 含义 |
|---|---|---|
| 引擎健康 | 正常 | 该节点所需能力当前可用 |
| 引擎健康 | 受影响 | 仍可工作，但部分路径或能力不可用 |
| 引擎健康 | 不可用 | 核心前置条件不满足，当前不能完成主路径 |
| 引擎健康 | 未知 | 数据未加载、接口不支持或检查失败 |
| 本次执行 | 未经过 / 执行中 / 符合预期 / 有差异 / 失败 / 证据不足 | 仅描述选中 Run |

颜色必须同时配合图标和文字。异常节点高亮实际受影响的后续边，但不能把未执行的可选分支误报为故障。

首页总体健康由 Daemon/Host 的 typed projection 返回。聚合优先级为 `不可用 > 受影响 > 正常`；存在未知关键检查时不得显示“可以正常工作”。

## 6. 问题等级与处理

结构化问题包含：

- `issue_id`、`category`、`severity`；
- 受影响的真实 stage IDs；
- 白话标题、影响说明；
- 证据引用和检查时间；
- 推荐操作、影响范围、是否可重试；
- 操作所有者和目标入口。

等级：

- **阻断**：主路径无法完成，对应总体“当前无法工作”。
- **影响**：主路径可继续，但特定能力不可用或行为偏离，对应“部分功能受到影响”。
- **提醒**：不影响当前工作，例如未启用的可选能力；不提升总体故障等级。

处理流程固定为：

1. 说明发生了什么；
2. 说明影响哪些节点、项目和未来 Run；
3. 展示推荐操作及将发生的精确变更；
4. 用户确认；
5. 调用所属权威执行；
6. 重新检查并展示结果。

系统不得静默修复。不可自动处理的问题跳转到正确的配置位置或提供可执行说明；不可重试时不显示无效“重试”。

## 7. 节点抽屉

节点抽屉固定提供三个一级页签，使用动词而非工程模块名：

### 7.1 看懂

- 这一步做什么；
- 它为什么存在；
- 当前状态及影响；
- 普通用户下一步。

### 7.2 执行证据

工作原理模式显示当前有效配置的可审计摘要；执行审计模式显示选中 Run 的冻结证据。

证据按“结论 → 证据 → 差异 → 处理”排列。确定性结论与语义建议必须分开：

- **确定性检查**：版本、来源、digest、装载顺序、matcher、Hook 返回状态、耗时、结构化错误、实际路由、权限决策。
- **审阅建议**：Prompt 是否清晰、是否冲突、是否可能产生歧义。必须标为“建议”，不能伪装成事实。

Prompt 审计显示有序 layer、来源、所有者、作用域、版本/digest、估算长度和有界脱敏预览。Run snapshot 保存 effective raw-prompt SHA-256，但不持久化或下发完整组合后的系统提示词。用户拥有的 Prompt Block 可查看全文；导入文件通过“查看来源”打开其权威位置；内置或敏感层只显示允许的摘要。

Hook 审计显示触发点、是否匹配、调用顺序、输入/输出的脱敏差异、决策、耗时、退出状态和失败策略。未匹配 Hook 由冻结快照与 dispatch input 推导，不伪造 invocation 事件。

Harness 审计显示 profile、scope、binding、published version、snapshot hash、prompt/hook semantics version 和 source drift。

### 7.3 配置

配置页签只展示该节点真正可配置的项目：

| 用户节点 | 配置入口 |
|---|---|
| 收到请求 | 会话范围、`SessionStart` / `UserPromptSubmit` Hook |
| 准备身份与规则 | Harness 绑定、Prompt Blocks、Prompt 来源与顺序、上下文 Hook |
| 调用 AI 模型 | 跳转 Provider 所有者；请求相关 Hook 如协议支持 |
| 使用能力 | Hook、工具保护、权限设置，以及 Capability Hub 中的 MCP/Skill/Extension/Agent Profile |
| 返回结果 | Compact/Stop/SessionEnd/Error Hook、结果 Prompt Block（如 schema 支持） |

“配置”不代表画布拥有所有数据。Provider、Capability Hub、权限与运行保护保持各自权威，画布通过委托入口打开所属编辑面。Harness 只编辑 Blueprint 中 schema 允许的 Hook overlay、Natives Hook 和 Prompt Block。

Harness 修改遵循 `Draft → Validate → Diff → Publish`。保存草稿不改变当前执行；发布前展示影响范围并要求确认；Active Run 始终使用其冻结配置。

## 8. 数据与权威边界

生产路径保持：

```text
Renderer → Tauri Host → UDS → Agent Daemon
```

需要增加或完成 typed workspace projection，至少包含：

- 经过验证的 global/project/session scope；
- 固定 stage/edge 及用户节点分组标识；
- 节点健康、结构化 issues 和检查时间；
- Hook/Prompt attachment 摘要和所有者引用；
- capability snapshot 引用与分组计数；
- Provider 和 runtime protection 只读摘要；
- 可选 Run frozen node state；
- `data_completeness`，明确哪些检查缺失或不支持。

Rust `assistant-protocol` 是 wire 类型唯一权威，前端绑定由生成流程产生。Renderer 不直接读 SQLite、项目 Hook 文件、Daemon socket，也不通过多份响应自行猜测统一状态。

Scheduler/Job 不属于执行引擎画布，继续由独立任务模块拥有。

## 9. 加载、空态和错误

- 加载：保留画布稳定尺寸，显示明确加载状态，不显示上一范围的数据冒充当前状态。
- 无项目：自动切换全局范围，并明确标注“全局引擎”。
- 无 Run：显示“还没有可审计的执行”，提供前往助理的入口。
- 无快照：显示“此执行没有可用的 Harness 证据”，状态为“证据不足”。
- 部分能力未实现：诚实显示“此版本暂不支持”，不渲染空编辑器。
- 错误：必须经 `classifyError()`，显示 `userMessage`、`actionHint` 和真实可用的重试入口；原始异常只进入受控诊断记录。
- 订阅：通过 Host adapter 转发的 Harness invalidation/run events 更新；不得在组件中高频轮询。

## 10. 安全、隐私与可访问性

- 凭证、leased key、环境 secret、完整敏感 payload 不进入 Renderer、Run snapshot、日志或导出。
- 审计证据在持久化前脱敏，并带 truncation metadata。
- 只有用户拥有且获准查看的 Prompt/Hook 内容可展开；其余显示摘要、digest 与所有者入口。
- 固定节点不能拖拽重连；平移和缩放不能阻止键盘访问节点。
- 节点使用原生按钮语义，支持焦点、Enter/Space、可见选中状态和屏幕阅读器标签。
- 状态不只依赖颜色；缩放、标签和抽屉不得导致布局跳动或文字遮挡。
- 所有可见文案、aria-label、空态和错误提示同时进入 `zh.ts` 与 `en.ts`。

## 11. 实施分层

### P0：看懂并能进入配置

- 执行引擎单一入口；
- 白话 5 节点画布和完整技术节点切换；
- 总体健康、结构化问题和确认式处理；
- 节点“看懂 / 执行证据 / 配置”抽屉；
- 各权威配置入口；
- 加载、空、错误和不支持状态。

### P1：真实 Run 审计闭环

- Run 选择器与冻结快照覆盖；
- Prompt Plan、Hook trace、Harness snapshot 和工具执行证据；
- 预期与实际差异；
- 受影响路径定位和审计导出入口。

P0 只能展示后端真实返回的现有证据。缺少 P1 wire/telemetry 时显示“证据不足”，不得用当前配置反推历史执行。

## 12. 测试与验收

### 12.1 单元与契约测试

- 11 个固定技术阶段到 5 个用户节点的映射完整且无重复遗漏；
- 总体健康聚合覆盖正常、影响、阻断、未知和部分数据缺失；
- 工作原理与执行审计切换不改变节点身份和选择上下文；
- 历史 Run 只读取 frozen snapshot/run events，不读取 Draft；
- Prompt/Hook/Harness 证据脱敏且有界；
- 配置入口按 authority 路由，不让 Harness 越权写 Provider/Capability 数据；
- unsupported capability 显示诚实状态；
- i18n 键完全一致；
- 所有用户错误经过 `classifyError`。

### 12.2 组件与交互测试

- 首次进入 5 秒内可见明确结论、范围和执行路径；
- 点击每个节点都能看到白话说明和真实配置入口；
- 问题节点显示影响与处理动作，执行前必须确认；
- 选择 Run 后同图显示节点执行状态；
- 无 Run、无快照、加载失败、Daemon 离线均有可操作状态；
- 320px、常规桌面和宽屏下无重叠、截断或抽屉遮死画布；
- 键盘可遍历模式、节点、页签和操作。

### 12.3 产品验收场景

1. 非技术用户打开页面，能说出“现在能不能工作”和 Native 引擎的 5 步处理过程。
2. Provider 不可用时，用户能在“调用 AI 模型”节点看到影响、原因和正确配置入口。
3. Hook 失败时，用户能定位到“使用能力”节点，看到脱敏输入/输出差异、失败策略和处理建议。
4. Prompt 顺序偏离预期时，用户能看到实际 layer 顺序、版本/digest 和差异，但看不到无权查看的敏感正文。
5. 用户修改 Prompt Block 或 Hook 后，只产生 Draft；校验、Diff 和确认发布后才影响未来 Run。

## 13. 非目标

- 不做自由拖拽、连线和重排的工作流构建器；
- 不允许修改固定执行状态机；
- 不从画布编辑外部 CLI Harness；
- 不把 Scheduler/Job 放回引擎能力；
- 不用 AI 评分替代可验证审计证据；
- 不为视觉完整性伪造健康、运行、Prompt、Hook 或能力数据。
