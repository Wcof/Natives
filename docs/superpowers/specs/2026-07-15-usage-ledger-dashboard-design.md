# 用量账本与个人主页看板设计

## 目标

个人主页保留十项用量指标，但统计必须来自可追溯的本地明细账本。页面读取本地聚合数据；只有用户点击“同步数据”才读取 Claude、Codex 等工具的本地日志。

## 已确认的界面行为

- 删除首页的 `Vibe Usage` 标题；顶部仅保留筛选、同步与导出操作。
- 保留现有十项指标卡片。
- 有数据源异常时显示一个非阻塞告警条：10 秒倒计时自动关闭，用户可点击关闭按钮立即关闭。同一份缓存快照在当前页面访问中关闭后不再显示。
- `zh` / `zh-CN` 下，卡片、图表、Hover 提示、告警、空状态和导出文案均使用中文；`en` 下均使用英文。禁止组件内硬编码另一种语言。

## 统计架构

### 本地事件账本

新建单一 `usage_ledger_events` 表，每条记录代表一个可计量的原始工具事件，包含：

- `source_id`：工具适配器 ID，例如 `claude`、`codex`、`gemini`、`opencode`、未来的 `atomcode` 与 `grok-cli`。
- `event_key`：适配器产生的稳定唯一键，表级 `UNIQUE(source_id, event_key)` 保证重复同步不会重复计量。
- `session_id`、`occurred_at_ms`、`project_path`、`model_id`、`terminal_id`。
- 输入、输出、缓存读、缓存写 Token；用户/助手消息数；可选费用和质量标记。
- `source_path`、`source_updated_at_ms`，用于追溯来源与增量同步。

另建 `usage_ledger_sync_state`，按 `source_id + source_path` 保存文件修改时间和已读行偏移。文件未变化时跳过；文件截断或替换时由适配器完整重读，唯一键防止重复写入。

### 适配器边界

定义一个内部 `UsageSourceAdapter`：发现来源文件、读取变更、把各工具格式标准化为账本事件。适配器不返回看板 DTO，也不直接计算全局汇总。

首批适配器：Claude、Codex。Gemini、OpenCode、Atomcode、Grok CLI 作为同一接口的后续独立实现；缺失或不支持的工具仅产生来源状态，不影响其他工具同步。

### 聚合与去重

同步完成后，使用 SQLite 从账本按时间范围、项目目录、来源、模型、终端聚合每日数据、小时活跃、会话和十项指标。会话与消息按账本唯一事件/会话 ID 去重。

ccusage 不作为 Claude/Codex 的第二份计量数据，避免重复累计；它保留为外部工具的独立适配器或来源校验，并在来源状态中明确标记。费用只对具有可靠定价的事件求和；不可得时维持 `null` 而非伪造为零。

### 缓存

沿用现有按时区的 dashboard snapshot：同步后写入快照；切换今天、24 小时、7/30/90 天与目录筛选只读本地账本/快照，不扫描日志也不显示全页加载。快照是读取优化，不是统计事实来源。

## 十项指标口径

1. 估算费用：有可靠单价事件的费用之和，并显示覆盖率。
2. 总 Token：输入 + 输出；缓存 Token 单独显示，不混入总 Token。
3. 输入 Token。
4. 输出 Token。
5. 缓存读取 Token，副值为缓存写入 Token。
6. 活跃时长：相邻事件间隔上限截断后的估算值，标记为估算。
7. 总时长：会话首末事件的跨度，按唯一会话汇总。
8. 会话数：唯一 `source_id + session_id` 数量。
9. 消息总数：用户与助手消息数之和。
10. 用户消息数。

同比/环比使用当前筛选范围紧邻的上一等长范围；前一范围无数据时显示 `—`，不显示错误的 `0%`。

## 错误与验证

- 单个来源、文件或行解析失败只生成来源告警，已入账数据继续可读。
- 数据库迁移均使用幂等 `CREATE TABLE IF NOT EXISTS`；已有快照不丢失。
- 增加最小回归测试：重复同步不增加事件数；文件增量仅写入新事件；同一来源的账本汇总正确；中文/英文指标和提示键均存在；告警倒计时与手动关闭。

## 非目标

- 不在页面加载、切换筛选或悬停时请求网络/API。
- 不为尚未存在的 Atomcode/Grok CLI 日志格式猜测解析规则；仅预留适配器边界，实际适配在获得真实样本后实现。
